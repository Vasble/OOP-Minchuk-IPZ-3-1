README — Лабораторна робота №2
Мета

Навчитися реалізовувати перевантажені конструктори (constructor overloading) в мові C#, дослідити механізм ланцюгового виклику конструкторів за допомогою ключового слова : this(), а також зрозуміти основні етапи життєвого циклу об'єкта в .NET: створення об'єкта оператором new, його використання в програмі та знищення збирачем сміття (Garbage Collector) із застосуванням деструктора (фіналізатора).

Хід роботи
Створено консольний проєкт lab2v13 у директорії OOP-<Прізвище> за допомогою команди dotnet new console -o OOP/lab2v13.
Реалізовано клас Library згідно з варіантом 13:
додано приватні поля _name, _address, _booksCount;
реалізовано публічні властивості Name, Address (з валідацією на порожні значення) та властивість BooksCount, доступну тільки для читання, значення якої змінюється лише через метод класу;
створено параметризований конструктор Library(name, address, initialBooksCount), який ініціалізує всі поля з перевіркою коректності даних;
створено другий конструктор Library(name, address), який викликає перший через : this(name, address, 0), реалізуючи ланцюговий виклик і уникаючи дублювання коду ініціалізації;
додано метод AddBook(string bookTitle), який збільшує кількість книг у бібліотеці та виводить відповідне повідомлення в консоль;
реалізовано деструктор ~Library(), який виводить повідомлення про знищення об'єкта збирачем сміття.
У методі Main створено три об'єкти класу Library з використанням обох конструкторів, викликано метод AddBook() для кожного об'єкта, після чого виведено підсумкову інформацію про кожну бібліотеку.
Наприкінці Main посилання на об'єкти явно обнулено (= null), а потім викликано GC.Collect() та GC.WaitForPendingFinalizers(), щоб примусово запустити збирач сміття та продемонструвати роботу деструкторів.
Проєкт скомпільовано та запущено командою dotnet run, результат роботи консолі зафіксовано у звіті.
Код завантажено до GitHub-репозиторію OOP-<Прізвище>/lab2v13.
Висновок

У ході виконання лабораторної роботи було закріплено практичні навички перевантаження конструкторів у C# та реалізації ланцюгового виклику через : this(), що дозволяє суттєво зменшити дублювання коду ініціалізації об'єктів. Було досліджено життєвий цикл об'єкта: створення в керованій купі (heap) за допомогою new, використання об'єкта, доки на нього існує хоча б одне посилання, та автоматичне знищення збирачем сміття після втрати всіх посилань. Виявлено, що момент виклику деструктора не є детермінованим і залежить від роботи GC, тому примусовий виклик GC.Collect() у навчальних цілях дозволив наочно продемонструвати спрацювання фіналізаторів, хоча в реальних програмах такий підхід не рекомендується через негативний вплив на продуктивність застосунку.
