# IndependentWork19 — самостійна робота №19

**Дисципліна:** Об'єктно-орієнтоване програмування
**Тема:** Дизайн винятків і політики retry: теорія та кейси Polly
**Платформа:** .NET 10, [Polly.Core](https://www.nuget.org/packages/Polly.Core) 8 (API `ResiliencePipelineBuilder`)

Опис кожного сценарію (проблема, обґрунтування стратегії, фрагмент коду, пояснення виводу), абзац про винятки проти `Result<T>`, висновки й відповіді на контрольні запитання — у [REPORT.md](REPORT.md).

## Що реалізовано

| Частина | Де | Суть |
|---------|----|------|
| Власний виняток | `Domain/InsufficientStockException.cs` | 3 стандартні конструктори + доменний, властивості `ProductSku`, `RequestedQuantity`, `AvailableQuantity`, `Shortage` |
| Демонстрація `try-catch-finally` | `Program.cs`, `Domain/Warehouse.cs` | Порядок `catch` від специфічного до загального, `finally`, `innerException` |
| Альтернатива — `Result<T>` | `Domain/Result.cs`, `Warehouse.TryReserve` | Очікувані неуспіхи без винятків |
| Сценарій 1 — **Retry** | `Scenarios/RetryScenario.cs` | API курсу валют: експоненційна затримка + jitter, `ShouldHandle` лише для тимчасових помилок |
| Сценарій 2 — **Circuit Breaker** | `Scenarios/CircuitBreakerScenario.cs` | Платіжний шлюз: стани Closed → Open → Half-Open → Closed |
| Сценарій 3 — **Timeout + Retry + Fallback** | `Scenarios/TimeoutFallbackScenario.cs` | Сервіс рекомендацій: тайм-аут на спробу, повтор, запасні дані з кешу |

Зовнішні сервіси імітуються в `Services/SimulatedServices.cs`: вони збоять за заданим сценарієм, тому вивід відтворюваний. Відрізняються лише затримки jitter і мілісекунди.


Під час першого запуску `dotnet` завантажить пакет `Polly.Core` з NuGet.
